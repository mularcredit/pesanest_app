1.2 Purpose

This document describes the technology and software architecture of PesaNest and specifies how the system integrates with KRA eTIMS to validate and fiscally sign tax invoices, credit notes and related documents in real time. It is prepared in support of the KRA eTIMS OSCU third-party integrator Go-Live application.

Section 6

Security, Reliability & Assumptions

6.1 Security Architecture

  • All KRA traffic is server-to-server over TLS 1.2+; the browser never handles KRA endpoints, tokens or the device key.
  • OAuth 2.0 client-credentials grant; short-lived Bearer tokens; per-request headers Authorization, tin, bhfId, cmcKey, apigee_app_id.
  • Application authentication via NextAuth (credentials + OTP) with bcrypt-hashed passwords and role-based access control.
  • Secrets stored as encrypted environment variables; least-privilege database access.

6.2 Reliability, Error Handling & Monitoring

  • Idempotency — accepted invoices are never re-transmitted; sequence numbers self-correct to KRA's expected value on conflict.
  • Resilience — during an eTIMS outage, documents are queued as PENDING and retried automatically on recovery; failed submissions can be resubmitted from the UI.
  • Observability — every request/response is logged with timestamp, receipt number and signature; failures are surfaced to operators.
